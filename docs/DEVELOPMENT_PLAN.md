# План разработки

## Подход

Работа идёт вертикальными срезами. Каждый этап заканчивается проверяемым результатом и может изменить следующий план. Большие системы не строятся заранее только «на будущее».

## Текущий статус — build 0.3

Этап 1 и первый UX-проход вертикального среза начаты. Созданы workspace, общий movement package и играбельный Chrome-клиент с процедурной test gym. Уже работают fixed loop 64 Hz, Pointer Lock, WASD, auto-bhop, ground/air acceleration, friction, capsule collision, slope sliding, таймер, рестарт, best time и debug HUD.

В build 0.3 добавлены главное меню и пауза, экраны карт/снаряжения/кейсов/настроек, 22 модели ножей, 6 комплектов рук/перчаток, три отделки ножа, соревновательный FPS HUD и облегчённая трасса с широкими платформами, мягкими рампами и возвратом на последний чекпоинт. Модели экипировки загружаются лениво и используют независимые скелеты.

Проверены typecheck, unit tests, production build, загрузка WASM, UI-сценарии и рендер сцены в Chromium/Google Chrome. Параметры профиля пока предварительные; comparative traces из CS2 ещё не сняты, поэтому build 0.3 не заявляет точное соответствие CS2.

## Этап 0. Зафиксировать решения

**Цель:** убрать неизвестные, которые меняют фундамент проекта.

- Зафиксировать актуальный desktop Google Chrome как главную платформу MVP и позже определить минимальный класс компьютера.
- Использовать утверждённые renderer, collision library, backend stack и package manager.
- Использовать auto-bhop при удержании клавиши прыжка.
- Зафиксировать solo-only MVP, отсутствие real-time multiplayer и настоящих платежей.
- Выбрать конкретный профиль CS2 bhop/surf-сервера для эталонных измерений.
- Выбрать единицы мира, fixed tick и формат movement preset.
- Описать собственное рабочее название и визуальную идентичность.
- Записать решения отдельными ADR в `docs/adr/`.

**Готово, когда:** выбран эталонный профиль движения, а первая версия архитектуры не содержит взаимоисключающих вариантов.

## Этап 1. Технический прототип движения

**Цель:** доказать, что выбранный браузерный стек подходит для точного parkour.

- Создать минимальную 3D-сцену с Pointer Lock и настраиваемой камерой.
- Разделить fixed simulation loop и render loop.
- Реализовать capsule collision, ground detection, лестницу/ступень и рестарт.
- Добавить диагностический HUD: FPS, frame time, velocity, ground state и surface normal.
- Проверить разные частоты рендера и временные просадки в актуальном desktop Chrome.
- Сделать серую test gym без финального арта.

**Готово, когда:** контроллер не зависит от FPS, не проваливается в типовые углы и стабильно работает на целевом устройстве.

## Этап 2. Вертикальный срез bhop

**Цель:** получить первое приятное полностью проходимое испытание.

- Реализовать ground acceleration, friction, air acceleration, wish direction и jump buffer.
- Добавить auto-bhop: удерживаемый прыжок срабатывает на первом допустимом simulation tick.
- Вынести параметры в версионированный movement preset.
- Реализовать spawn, checkpoints, finish, kill zones, timer и мгновенный restart.
- Записывать input replay и локальный ghost.
- Создать короткую учебную и одну небольшую bhop-трассу.
- Провести игровые тесты и настроить физику по данным, а не по ощущению разработчика в одиночку.

**Готово, когда:** новый игрок завершает учебную трассу, опытный может улучшать время, а сохранённый replay воспроизводится стабильно.

## Этап 3. Surf и формат карт

**Цель:** подтвердить вторую ключевую механику и контентный pipeline.

- Реализовать multi-plane clipping и поведение на наклонных поверхностях.
- Отделить walkable slopes от surf surfaces.
- Добавить телеметрию угла входа, сохранения скорости и причины срыва.
- Утвердить manifest карты, collision mesh и правила версионирования.
- Создать Blender export checklist и автоматическую валидацию карты.
- Сделать одну короткую surf-карту и mixed-секцию.

**Готово, когда:** surf не ломает обычную ходьбу, карта проходит автоматическую проверку, а смена visual mesh не меняет collision checksum без новой версии.

## Этап 4. Backend и честные результаты

**Цель:** превратить локальный прототип в серверно подтверждаемую игру.

- Добавить гостевые сессии, профиль и настройки.
- Создать каталог опубликованных карт и movement presets.
- Принимать run replay как `pending`.
- Поднять отдельный verifier, воспроизводящий движение на сервере.
- Хранить accepted/rejected status и причину отклонения.
- Создать leaderboard, разделённый по версии карты, preset и assists.
- Добавить rate limiting, лимиты payload и базовую наблюдаемость.

**Готово, когда:** изменённое клиентом время не принимается, корректный replay подтверждается, повторная отправка не создаёт дубликат награды.

## Этап 5. Валюта, кейсы и инвентарь

**Цель:** добавить метацикл без влияния косметики на gameplay.

- Создать wallet ledger вместо одного изменяемого числа баланса.
- Начислять награду только за accepted run.
- Настроить защиту от бессмысленного фарма одной короткой попытки.
- Создать каталог cosmetics и loadout.
- Добавить demo top-up packages и идемпотентное тестовое начисление через wallet ledger.
- Во всём demo-flow явно показывать, что деньги не списываются, и не собирать платёжные данные.
- Создать версионированные case/drop tables с видимыми шансами.
- Реализовать транзакционное, идемпотентное открытие.
- Добавить duplicate policy: дубликаты остаются, конвертируются или дают shards — решение нужно принять заранее.
- Проверить невозможность отрицательного баланса и двойного списания.

**Готово, когда:** полный путь «пройти → получить → открыть → экипировать» работает, а экономика остаётся корректной при повторах запросов и сетевых ошибках.

## Этап 6. UX, доступность и визуальный слой

**Цель:** сделать игру спокойной, понятной и собственной по стилю.

- Главное меню: продолжить, карты, инвентарь, кейсы, настройки.
- Экран карты: сложность, тип, личный рекорд, награда, режим помощи.
- HUD показывает только нужное в движении; расширенная телеметрия включается отдельно.
- Экран финиша быстро предлагает restart/next map без принудительной длинной анимации.
- Анимация кейса имеет skip и учитывает `prefers-reduced-motion`.
- Контраст текста не ниже 4.5:1, фокус клавиатуры видим, все кнопки имеют текстовые названия.
- Web shell адаптивен; сама игра в MVP честно сообщает, что оптимизирована под desktop Chrome с keyboard/mouse.
- Звуки и эффекты поддерживают ритм, но не перегружают игрока.

**Готово, когда:** основные сценарии проходят клавиатурой, интерфейс не блокирует быстрый рестарт и визуально не воспринимается как копия CS2.

## Этап 7. Контент и закрытый тест

**Цель:** проверить удержание и сложность на реальных игроках.

- Подготовить минимум три карты разных типов и понятное обучение.
- Ввести события аналитики без записи лишних персональных данных.
- Измерять completion rate, число рестартов, участки потери скорости и время сессии.
- Проверить баланс наград и темп открытия косметики.
- Добавить feedback/report flow.
- Исправить главные точки выхода до расширения каталога.

**Готово, когда:** игроки без объяснений понимают основной цикл, большинство проходит tutorial, а ошибки физики отделены от ошибок дизайна трассы.

## Этап 8. Публичный MVP

**Цель:** безопасный и наблюдаемый релиз.

- CI для lint, typecheck, unit, replay и integration tests.
- Версионированные миграции, backup/restore rehearsal и rollback plan.
- CDN cache strategy для неизменяемых map assets.
- Метрики API, verifier queue, ошибок клиента и производительности карты.
- Privacy policy, terms, лицензии ассетов и возрастные ограничения по результату юридической проверки.
- Нагрузочный тест отправки результатов и открытия кейсов.
- Постепенный rollout с feature flags.

**Готово, когда:** есть мониторинг, восстановление данных, понятный rollback и ограниченная аудитория может играть без ручного вмешательства разработчика.

## После MVP

Только по данным пользователей рассматривать новые карты, сезоны, редактор, social ghosts и real-time multiplayer. Торговля, платежи и предметы с денежной стоимостью — отдельный продуктовый и юридический проект, а не небольшое продолжение текущей экономики.

## Порядок первых реализационных задач после утверждения плана

1. Зафиксировать эталонный CS2 server profile и сценарии измерения.
2. ADR по fixed tick и единицам мира.
3. Workspace/config без функционального кода.
4. Клиентский boot screen и пустой game canvas.
5. Fixed loop и input sampling.
6. Test gym и collision queries.
7. Movement controller с comparative/unit/golden tests.
8. Checkpoints, timer, restart и replay.
9. Первый bhop vertical slice.

Backend начинается после пункта 9, кроме минимального контракта replay, который проектируется вместе с movement package.
